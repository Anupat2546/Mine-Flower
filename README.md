# Mine Flowers — เว็บไซต์ร้านดอกไม้ออนไลน์

โค้ดชุดนี้เป็นเว็บไซต์แบบ static (HTML/CSS/JS ล้วน ไม่ต้องมี server/database)
ทำงานได้ทันทีในเบราว์เซอร์ และเมื่อลูกค้ากดสั่งซื้อ ระบบจะเปิดแอป **LINE**
พร้อมข้อความสรุปออเดอร์ ส่งตรงเข้าไลน์ร้านของคุณโดยอัตโนมัติ

## ไฟล์ในโปรเจกต์
- `index.html` — หน้าเว็บร้าน (แคตตาล็อก, ออกแบบช่อเอง, ตะกร้า, แนบสลิป)
- `admin.html` — หน้าตั้งค่าสำหรับเจ้าของร้าน (จัดการสต็อก มี login)
- `style.css` — ธีมสี/ฟอนต์/ดีไซน์หน้าร้าน (โทนชมพูพาสเทล-เขียวเซจ-ครีม)
- `admin.css` — ธีมของหน้า admin
- `inventory-config.js` — ⚙️ ค่าคอนฟิกร้าน + ข้อมูลสต็อกเริ่มต้น (ใช้ร่วมกันทั้ง 2 หน้า)
- `script.js` — ตะกร้า, สินค้า, ออกแบบช่อเอง, แนบสลิป (+ ตรวจสลิปอัตโนมัติผ่าน SlipOK), ส่งออเดอร์เข้า LINE
- `admin.js` — ระบบล็อกอิน + แก้ไขสต็อกของหน้า admin
- `auth.js` — เข้าสู่ระบบลูกค้าด้วย Google / Facebook / LINE (Firebase Auth)
- `functions/index.js` — Cloud Function ฝั่งเซิร์ฟเวอร์: login LINE, ตรวจสลิป และส่งออเดอร์+สลิปเข้า LINE ร้านโดยตรง
- `functions/package.json` — dependency ของ Cloud Functions
- `README.md` — ไฟล์นี้

## ⭐ ฟีเจอร์ใหม่ที่เพิ่มเข้ามา

### 1) แนบสลิปโอนเงิน
ลูกค้าต้องแนบรูปสลิปก่อนกดยืนยันสั่งซื้อ (ระบบจะเตือนถ้ายังไม่แนบ)
เมื่อกดยืนยัน ระบบจะ**พยายามคัดลอกรูปสลิปเข้าคลิปบอร์ดของมือถือลูกค้า
อัตโนมัติ** แล้วเปิดแชท LINE พร้อมข้อความสรุปออเดอร์ — ลูกค้าแค่กด "วาง"
(Paste) รูปในแชทแล้วกดส่งอีกครั้งเดียว รูปสลิปก็จะถึงร้าน

> ⚠️ ข้อจำกัดสำคัญ: เว็บไซต์แบบ static (ไม่มี server) **ไม่สามารถส่งไฟล์
> รูปแนบไปกับลิงก์ LINE ได้โดยอัตโนมัติ 100%** เพราะ LINE ไม่อนุญาตให้เว็บ
> ส่งข้อความ/ไฟล์แทนผู้ใช้ได้ (เพื่อความปลอดภัย) วิธี "คัดลอก→วาง" ด้านบน
> เป็นวิธีที่ใกล้เคียงระบบอัตโนมัติที่สุดเท่าที่ทำได้โดยไม่ต้องมี backend
> ถ้าต้องการให้สลิปแนบอัตโนมัติแบบ 100% (ไม่ต้องกดวางเอง) จะต้องมีระบบ
> หลังบ้าน (เช่น Firebase + LINE Messaging API) แจ้งได้ถ้าอยากอัปเกรด

### 1.1) ตรวจสลิปโอนเงินอัตโนมัติด้วย SlipOK (ใหม่)
ทันทีที่ลูกค้าแนบรูปสลิป ระบบจะส่งรูปไปให้ **SlipOK** ตรวจสอบอัตโนมัติ
เบื้องหลัง (ไม่บล็อกลูกค้า สั่งซื้อต่อได้เลยแม้ผลตรวจจะยังไม่ออกหรือไม่ผ่าน)
แล้วขึ้นป้ายเล็กๆ ใต้รูปสลิปแต่ละรูปให้ลูกค้าเห็นทันที:
- ✅ **ยอดตรง** — ยอดเงินในสลิปตรงกับยอดในตะกร้า และโอนเข้าบัญชีหลักของร้านจริง
- ⚠️ **ตรวจสอบอีกครั้ง** — เช่น ยอดไม่ตรง, โอนผิดบัญชี, หรือเป็นสลิปที่เคยใช้มาแล้ว
  (แตะ/ชี้ที่ป้ายเพื่อดูรายละเอียดสาเหตุ)
- (ไม่มีป้าย) — ยังไม่ได้ตั้งค่า `CONFIG.SLIPOK_VERIFY_URL` หรือเชื่อมต่อไม่ได้ชั่วคราว

> ⚠️ ตามที่แจ้งไว้: ระบบนี้แค่ **เตือนลูกค้าเอง** ไม่ได้บล็อกการสั่งซื้อ และ
> ไม่ได้บันทึกผลไว้ที่ไหนในเว็บ (SlipOK จะเก็บประวัติสลิปที่เคยตรวจไว้ฝั่งเขา
> เพื่อใช้กันสลิปซ้ำ) ร้านยังต้องตรวจสลิปที่ลูกค้าส่งเข้า LINE เองอีกครั้งก่อน
> จัดส่งของอยู่ดี — ถ้าอยากให้ระบบบันทึกผลตรวจ/แจ้งร้านอัตโนมัติผ่าน LINE ด้วย
> แจ้งได้ ทำต่อได้ไม่ยาก

**วิธีตั้งค่า** (ต้องมี Firebase Cloud Function เหมือนระบบล็อกอิน LINE ด้านบน):
1. สมัคร/เข้า [SlipOK Dashboard](https://slipok.com) สร้าง "สาขา" (Branch) แล้ว
   ผูกบัญชีธนาคารของร้าน (บัญชีเดียวกับที่ใส่ใน `CONFIG.BANK_ACCOUNT_NUMBER`)
   จะได้ **Branch ID** และ **API Key**
2. ในเครื่องที่ลง Firebase CLI แล้ว (ขั้นตอนเดียวกับตอนตั้งค่า LINE Login):
   ```
   firebase init functions   # ถ้ายังไม่เคยทำ
   ```
   แทนที่ `functions/index.js` ด้วยไฟล์ `index.js` ที่แนบมา และ
   `functions/package.json` ด้วยไฟล์ `package.json` ที่แนบมา (ไฟล์เดียวกับที่
   ใช้กับ `lineLogin` — ตอนนี้มีทั้ง 2 ฟังก์ชันรวมกันอยู่ในไฟล์เดียว)
3. เพิ่มค่าความลับใหม่ในไฟล์ `functions/.env`:
   ```
   SLIPOK_API_KEY=รหัส API Key จาก SlipOK
   SLIPOK_BRANCH_ID=รหัสสาขา (Branch ID) จาก SlipOK
   ```
4. Deploy: `firebase deploy --only functions`
5. คัดลอก URL ของฟังก์ชัน `verifySlip` ที่ได้ ไปใส่ใน `inventory-config.js`:
   ```js
   CONFIG.SLIPOK_VERIFY_URL = "https://YOUR-REGION-YOUR-PROJECT.cloudfunctions.net/verifySlip";
   ```
6. รีเฟรชหน้าเว็บ แนบรูปสลิปทดสอบดูป้ายผลลัพธ์ใต้รูปได้เลย

> หมายเหตุ: SlipOK คิดค่าบริการตามจำนวนครั้งที่ตรวจสลิป (มีแพ็กเกจฟรีจำนวน
> จำกัดให้ทดลองก่อน) — เช็คโควต้า/แพ็กเกจได้ที่ SlipOK Dashboard

### 2) ส่งออเดอร์และสลิปเข้า LINE ร้านโดยตรง

ระบบมี Cloud Function `submitOrder` แล้ว เมื่อ deploy และตั้งค่าครบ ลูกค้าจะกดยืนยันครั้งเดียว ระบบจะส่งข้อความข้อมูลลูกค้าและรูปสลิปเข้า LINE ร้านทันที โดยไม่ต้องคัดลอก/วางเอง

1. สร้างหรือใช้ LINE Messaging API Channel แล้วเปิดใช้งาน Messaging API
2. ตั้งค่า Webhook ชั่วคราวหรือใช้ webhook ของบอทเพื่อหา `userId` ของบัญชี LINE ร้าน (ค่า `LINE_SHOP_USER_ID` ต้องเป็น userId จริง ไม่ใช่ Basic ID ที่ขึ้นต้นด้วย `@`)
3. ตั้งค่า secrets ในโฟลเดอร์ Cloud Functions:
  ```
  firebase functions:secrets:set LINE_MESSAGING_ACCESS_TOKEN
  firebase functions:secrets:set LINE_SHOP_USER_ID
  ```
  ให้วาง Channel Access Token และ userId ตามลำดับเมื่อ CLI ถาม
4. Deploy:
  ```
  firebase deploy --only functions
  ```
5. นำ URL ของฟังก์ชัน `submitOrder` ไปใส่ใน `inventory-config.js`:
  ```js
  ORDER_SUBMIT_URL: "https://YOUR-REGION-YOUR-PROJECT.cloudfunctions.net/submitOrder",
  ```

สลิปจะถูกอัปโหลดไปยัง Firebase Storage และส่งเป็นรูปเข้า LINE ด้วย signed URL ที่หมดอายุภายใน 1 ชั่วโมง ถ้ายังไม่ตั้งค่า `ORDER_SUBMIT_URL` ระบบจะกลับไปใช้การแชร์/คัดลอกแบบเดิมอัตโนมัติ

### 2) ออกแบบช่อของคุณเอง (Custom Bouquet Builder)
ลูกค้ากด "ออกแบบช่อของคุณเอง" ในหน้าแคตตาล็อก แล้วเลือกทีละหมวด:
ชนิดดอกไม้ → สีดอกไม้ → กระดาษ/ห่อช่อ → โบว์ ราคาจะรวมอัตโนมัติจาก
ราคาเริ่มต้น (`CONFIG.CUSTOM_BASE_PRICE`) บวกส่วนเพิ่มของแต่ละตัวเลือก
ตัวเลือกที่สต็อก = 0 จะขึ้น "หมด" และกดเลือกไม่ได้ทันที

### 3) หน้าตั้งค่าสำหรับเจ้าของร้าน (`admin.html`)
เปิดไฟล์ `admin.html` แล้วใส่รหัสผ่าน (ตั้งไว้ที่ `CONFIG.ADMIN_PASSWORD`
ในไฟล์ `inventory-config.js` — **แก้รหัสผ่านนี้ก่อนใช้งานจริง!**)
ในหน้านี้เจ้าของร้านสามารถ:
- เปิด/ปิดการขาย (ซ่อนตัวเลือกจากลูกค้าทันที) ของดอกไม้แต่ละชนิด/สี/กระดาษห่อ/โบว์
- แก้ไข **จำนวนคงเหลือ** — ใส่ 0 = ระบบขึ้น "หมด" ให้ลูกค้าเห็นทันที
- แก้ไขชื่อ, สี (color picker), ราคาบวกเพิ่ม
- เพิ่ม/ลบรายการใหม่ได้เอง ไม่ต้องแก้โค้ด
- กด "บันทึกการเปลี่ยนแปลง" เพื่อบันทึกค่า

> ⚠️ ข้อจำกัดสำคัญ: ค่าที่บันทึกในหน้า admin ถูกเก็บไว้ใน **localStorage
> ของเบราว์เซอร์เครื่องนั้น ๆ เท่านั้น** ไม่ได้ซิงก์ขึ้นออนไลน์ให้ทุกคนเห็น
> พร้อมกัน ถ้าเปิด `admin.html` แล้วแก้สต็อกจากมือถือร้าน แต่ลูกค้าคนอื่น
> เข้าเว็บจากมือถือของเขาเอง **ลูกค้าจะยังเห็นสต็อกค่าเริ่มต้นในโค้ด
> ไม่ใช่ค่าที่ร้านเพิ่งแก้** เพราะเว็บนี้ยังไม่มีฐานข้อมูลกลาง (ตามที่ขอไว้
> ตอนแรกว่ายังไม่ต้องขึ้นเว็บจริง/ไม่ต้องมี backend)
>
> เหมาะสำหรับ: ทดสอบระบบ, ใช้งานจากเบราว์เซอร์เดียวที่ประจำร้าน (เช่น
> คอมที่หน้าร้านเปิดเว็บทั้ง 2 หน้าค้างไว้)
>
> ถ้าต้องการให้สต็อกอัปเดตเรียลไทม์และเห็นตรงกันทุกอุปกรณ์ (สิ่งที่ร้าน
> ค้าออนไลน์จริงส่วนใหญ่ต้องการ) แนะนำให้อัปเกรดไปต่อฐานข้อมูลฟรีอย่าง
> **Firebase Firestore** (ของ Google) — แจ้งผมได้เลยถ้าอยากให้ทำขั้นตอนนี้
> ต่อ ใช้เวลาไม่นานเพราะโครงสร้างโค้ดตอนนี้รองรับการสลับไปใช้ฐานข้อมูล
> ได้ง่ายอยู่แล้ว (ฟังก์ชัน loadInventory/saveInventory)

### 4) ข้อมูลผู้สั่ง/ผู้รับแยกกันชัดเจน
ฟอร์มตอนนี้แยก 2 ส่วน:
- **ผู้สั่งซื้อ**: ชื่อจริง, นามสกุล, ชื่อเล่น, เบอร์โทร
- **ผู้รับดอกไม้**: ชื่อจริง, นามสกุล, ชื่อเล่น, เบอร์โทร, ที่อยู่จัดส่ง

ข้อมูลทั้งหมดจะถูกใส่ในข้อความสรุปที่ส่งเข้า LINE ร้านโดยอัตโนมัติ

## ตั้งค่าก่อนใช้งานจริง (สำคัญมาก!)

เปิดไฟล์ `inventory-config.js` แล้วแก้ค่าใน `CONFIG`:

```js
const CONFIG = {
  LINE_OA_ID: "@yourlineid",        // 👈 Basic ID ของ LINE OA ร้านคุณ
  SHOP_NAME: "Mine Flowers",
  HERO_IMAGE: "",                    // 👈 รูปพื้นหลัง Hero (ถ้ามี)
  SHOWCASE_VIDEO: "",                // 👈 วิดีโอพื้นหลัง Hero (ถ้ามี)
  CUSTOM_BASE_PRICE: 390,            // 👈 ราคาเริ่มต้นของช่อออกแบบเอง
  ADMIN_PASSWORD: "mineflowerz2026", // 👈 เปลี่ยนรหัสผ่าน admin ก่อนใช้จริง!
};
```

**วิธีหา LINE OA Basic ID:**
1. เข้า [LINE Official Account Manager](https://manager.line.biz/)
2. เลือกร้านของคุณ → เมนู "การตั้งค่า" (Settings) → "Basic ID"
3. จะได้ค่ารูปแบบ `@xxxxxxx` เอามาใส่แทน `@yourlineid`

> ถ้าคุณยังไม่มี LINE Official Account (ฟรี) สมัครได้ที่ https://www.linebiz.com/th/services/line-official-account/

ถ้าอยากแก้รายการสินค้าสำเร็จรูป/ราคา แก้ในไฟล์ `script.js` ที่ตัวแปร
`PRODUCTS` ส่วนสต็อกดอกไม้/สี/ห่อ/โบว์สำหรับช่อออกแบบเอง แก้ผ่านหน้า
`admin.html` ได้เลยโดยไม่ต้องแตะโค้ด

## วิธีใส่รูปภาพ/วิดีโอจริงของร้าน

โครงสร้างโฟลเดอร์รูปภาพถูกเตรียมไว้ให้แล้ว:

```
mine-flowerz/
├── images/
│   ├── hero.jpg              👈 รูป/ปกหน้าเว็บ (ถ้าต้องการ)
│   ├── products/              👈 รูปสินค้าแต่ละช่อ
│   │   ├── rose-pink.jpg
│   │   └── ...
│   └── gallery/               👈 รูปบรรยากาศร้าน/ผลงานเก่า
│       ├── shop-front.jpg
│       └── ...
└── videos/
    └── shop-intro.mp4         👈 วิดีโอแนะนำร้าน (ถ้าต้องการ)
```

### 1) รูปสินค้าในการ์ด (แคตตาล็อก)
เปิด `script.js` หาตัวแปร `PRODUCTS` แล้วใส่ path รูปในช่อง `img` ของสินค้านั้น:

```js
{
  id: "p1",
  name: "ช่อกุหลาบชมพูหวาน",
  desc: "กุหลาบชมพูพาสเทล 12 ดอก ห่อกระดาษคราฟท์",
  price: 590,
  color: "var(--rose)",
  img: "images/products/rose-pink.jpg",   // 👈 ใส่ path รูปตรงนี้
},
```
ลากไฟล์รูปไปวางในโฟลเดอร์ `images/products/` แค่นั้นจบ ถ้าปล่อย `img: ""`
ไว้ ระบบจะวาดไอคอนดอกไม้ SVG ให้แทนโดยอัตโนมัติ (ใช้ระหว่างรอรูปจริงได้)

### 2) รูปหรือวิดีโอพื้นหลังหน้า Hero (ด้านบนสุดของเว็บ)
เปิด `script.js` หาตัวแปร `CONFIG` ที่บรรทัดบนสุดของไฟล์:

```js
const CONFIG = {
  ...
  HERO_IMAGE: "images/hero.jpg",          // 👈 ใส่รูป หรือ
  SHOWCASE_VIDEO: "videos/shop-intro.mp4", // 👈 ใส่วิดีโอ (ถ้ามีทั้งคู่ วิดีโอจะถูกใช้ก่อน)
};
```
วิดีโอจะเล่นวนอัตโนมัติแบบไม่มีเสียง (จำเป็นสำหรับให้เบราว์เซอร์ยอม
auto-play) เหมาะกับคลิปสั้น ๆ 5-15 วินาทีโชว์การจัดดอกไม้/หน้าร้าน

### 3) แกลเลอรีรูปบรรยากาศร้าน (ผลงานเก่า/หน้าร้าน)
เปิด `script.js` หาตัวแปร `GALLERY_IMAGES` แล้วใส่ path รูปในลิสต์:

```js
const GALLERY_IMAGES = [
```

### 4) เอาคลิปจาก TikTok/Instagram มาฝังในเว็บ (ไม่ต้องอัปโหลดไฟล์เอง)
ถ้าอยากโชว์คลิปที่โพสต์ไว้ใน TikTok/IG อยู่แล้วโดยไม่ต้องดาวน์โหลดไฟล์วิดีโอมา
เก็บเอง ใช้วิธี **embed** แทนได้ วิธีคือ:
1. เปิดโพสต์ IG Reel หรือ TikTok ที่ต้องการ
2. กด "แชร์" (Share) → เลือก "ฝัง" (Embed)
3. คัดลอกโค้ด `<blockquote>` หรือ `<iframe>` ที่ได้มา
4. วางแทนที่ใน `index.html` ตรงส่วนที่ต้องการ (เช่นในหัวข้อ Gallery)

โค้ดตัวอย่าง (จะได้จากปุ่ม "ฝัง" ของ TikTok):
```html
<blockquote class="tiktok-embed" cite="https://www.tiktok.com/@mine.flower5/video/xxxx" ...>
  ...
</blockquote>
<script async src="https://www.tiktok.com/embed.js"></script>
```

### เกร็ดเรื่องขนาดไฟล์ (เว็บโหลดเร็ว/ไม่หนัก)
- รูปภาพ: แนะนำไฟล์ `.jpg`/`.webp` ขนาดไม่เกิน ~500KB ต่อรูป และความกว้างไม่เกิน 1600px
  (ใช้เว็บฟรีอย่าง [squoosh.app](https://squoosh.app) บีบอัดได้ง่าย ๆ)
- วิดีโอ: ใช้ `.mp4` (H.264) ความยาวสั้น ๆ ไม่เกิน 15-20 วินาที ขนาดไฟล์ไม่เกิน ~5-8MB
  เพื่อให้โหลดเร็วบนมือถือ

## วิธีรันทดสอบใน VS Code

1. เปิดโฟลเดอร์นี้ทั้งโฟลเดอร์ด้วย VS Code (`File > Open Folder...`)
2. ติดตั้งส่วนขยาย **Live Server** (โดย Ritwick Dey) จากแท็บ Extensions (`Ctrl+Shift+X` พิมพ์ "Live Server")
3. คลิกขวาที่ไฟล์ `index.html` → เลือก **"Open with Live Server"**
4. เบราว์เซอร์จะเปิดเว็บไซต์ให้อัตโนมัติที่ `http://127.0.0.1:5500`
5. ทดสอบ: เลือกช่อดอกไม้ → ใส่ตะกร้า → กรอกข้อมูลจัดส่ง → กด "ยืนยันสั่งซื้อ"
   ระบบจะเปิดแท็บใหม่ไปที่ LINE พร้อมข้อความสรุปออเดอร์

> ถ้าเปิดไฟล์ `index.html` ตรง ๆ (ดับเบิลคลิก) ก็ใช้งานได้เช่นกัน แต่แนะนำ
> ให้ใช้ Live Server เพื่อให้ฟอนต์และการรีเฟรชหน้าทำงานราบรื่นกว่า

## เมื่อลูกค้ากดสั่งซื้อจะเกิดอะไรขึ้น
1. เว็บไซต์รวบรวมรายการสินค้าในตะกร้า + ข้อมูลผู้รับ (ชื่อ/เบอร์/ที่อยู่/วันที่/หมายเหตุ)

   ของลูกค้า (หรือ LINE บนคอม) พร้อมข้อความสรุปออเดอร์ที่พิมพ์ไว้ให้แล้ว
4. ลูกค้ากดส่งข้อความในแอป LINE อีกครั้งเดียว ข้อความจะเด้งเข้าไลน์ร้าน
   ของคุณทันที — คุณเห็นแจ้งเตือนที่มือถือได้เลยแบบเรียลไทม์

> หมายเหตุ: ลิงก์รูปแบบนี้จะเปิดหน้าต่างแชทให้ แต่ลูกค้าต้องกด "ส่ง" อีกครั้ง
> ในแอป LINE เอง (เป็นข้อจำกัดของ LINE ที่ไม่ให้เว็บส่งข้อความแทนผู้ใช้ได้

## โดเมนเว็บไซต์ (เช่น www.mineflower.com)

**สำคัญ: การ "เปลี่ยน URL" ไม่สามารถทำได้ด้วยการแก้โค้ดอย่างเดียว** เพราะ
ตอนนี้เว็บยังรันอยู่แค่ในเครื่องคุณผ่าน VS Code Live Server (URL จะเป็น
`http://127.0.0.1:5500/...` เท่านั้น ซึ่งเปิดได้แค่ในเครื่องคุณคนเดียว)

ถ้าต้องการให้เว็บมี URL จริงเป็น `www.mineflower.com` ที่ใครก็เข้าได้
ต้องทำ 2 ขั้นตอนนอกเหนือจากโค้ด:

1. **ซื้อโดเมน** `mineflower.com` จากผู้ให้บริการ เช่น Google Domains
   (ปัจจุบันย้ายไปอยู่ Squarespace), Namecheap, หรือ GoDaddy (ราคาปีละ
   ประมาณ 400-1,200 บาท ขึ้นกับผู้ให้บริการ)
2. **อัปโหลดเว็บขึ้นโฮสติ้งฟรี** เช่น GitHub Pages หรือ Firebase Hosting
   แล้วตั้งค่า **"เชื่อมโดเมนกำหนดเอง" (Custom Domain)** ให้ชี้มาที่โดเมนที่
   ซื้อมา ขั้นตอนนี้ใช้เวลาประมาณ 10-30 นาที

ผมเตรียมโค้ดให้พร้อมสำหรับตอนที่คุณย้ายขึ้นเว็บจริงแล้ว โดยเพิ่ม meta tag
`canonical` และ `Open Graph` ที่ชี้ไปยัง `https://www.mineflower.com/` ไว้ใน
`index.html` แล้ว (สำหรับตอน SEO/แชร์ลิงก์ไปโซเชียล) — **เมื่อซื้อโดเมนจริง
แล้ว แจ้งผมได้เลย ผมจะช่วยเดินเรื่อง GitHub Pages/Firebase + เชื่อมโดเมนให้
ครบทุกขั้นตอน**

## รองรับทุกอุปกรณ์ (PC, มือถือ, แท็บเล็ต, iOS, Android, MacBook)

เว็บนี้เขียนด้วย responsive design ตั้งแต่แรกอยู่แล้ว (ปรับเลย์เอาต์ตามขนาด
จออัตโนมัติ) และเพิ่มการปรับปรุงเพื่อให้ใช้งานลื่นขึ้นบนทุกอุปกรณ์:

- **เมนูแฮมเบอร์เกอร์บนจอเล็ก** — เมนู "ช่อดอกไม้ / วิธีสั่งซื้อ / ติดต่อร้าน"
  แต่ก่อนหายไปเฉย ๆ บนมือถือ ตอนนี้สลับเป็นปุ่มแฮมเบอร์เกอร์ (☰) เปิดเป็น
  เมนูเลื่อนออกจากขวาแทน
- **breakpoints ละเอียดขึ้น** — ปรับขนาดตัวอักษร ระยะห่าง จำนวนคอลัมน์สินค้า
  ให้เหมาะกับ: จอมือถือเล็ก (< 380px), มือถือทั่วไป (< 640px), แท็บเล็ต
  (< 1024px), และจอ PC/MacBook จอกว้าง (> 1440px)
- **รองรับรอยบาก iPhone (notch/Dynamic Island)** — เพิ่ม `safe-area-inset`
  กันเนื้อหาโดนรอยบากหรือแถบ home indicator บัง
- **ปุ่มกดขนาดเหมาะกับนิ้ว** — ปุ่มบนมือถือมีพื้นที่แตะอย่างน้อย ~38-44px
  ตามแนวทางของ Apple/Google
- **เพิ่มลงหน้าจอโฮมได้เหมือนแอป** — เพิ่ม `manifest.json` และ meta tag ของ
  iOS ให้ลูกค้ากด "เพิ่มลงหน้าจอโฮม" จาก Safari (iOS) หรือ Chrome (Android)
  แล้วเปิดเว็บได้เหมือนเปิดแอปจริง (ไม่มีแถบที่อยู่เว็บโชว์)

  **ต้องเพิ่มไอคอนก่อนฟีเจอร์นี้จะสมบูรณ์:** เตรียมรูปโลโก้ร้านสี่เหลี่ยม
  จัตุรัส 2 ขนาด (192x192px และ 512x512px) ไปวางที่ `images/icon-192.png`
  และ `images/icon-512.png` ตามลำดับ แล้วสำหรับ iOS ให้เพิ่มรูปขนาด 180x180px
  ที่ `images/icon-180.png` แล้วลบคอมเมนต์บรรทัด
  `<link rel="apple-touch-icon" ...>` ออกในไฟล์ `index.html` (อยู่ใน `<head>`)

เว็บนี้ไม่มีโค้ดเฉพาะแพลตฟอร์ม (ไม่ต้องเขียนแยกเวอร์ชัน iOS/Android/Mac)
เพราะเป็นเว็บไซต์ธรรมดาที่เปิดผ่านเบราว์เซอร์ — Safari บน iPhone/iPad/Mac,
Chrome บน Android/Windows, Edge, Firefox ล้วนแสดงผลเว็บเดียวกันได้หมด
ไม่ต้องมีแอปแยกในแต่ละแพลตฟอร์ม

## ระบบส่งออเดอร์เข้าร้าน 3 ระดับ (ทำไมบางทีขึ้นหน้าต่างแชร์ของเครื่อง)

ตอนลูกค้ากด "ยืนยันสั่งซื้อ" ระบบจะลองทำตามลำดับนี้ ใช้วิธีแรกที่ทำงานได้:

1. **ส่งอัตโนมัติผ่าน Cloud Function** (`CONFIG.ORDER_SUBMIT_URL`) — เงียบ
   ไม่มี popup ใดๆ ข้อมูล+สลิปเด้งเข้า LINE ร้านเองทันที ใช้ได้เหมือนกัน
   ทุกอุปกรณ์ (PC/มือถือ/Mac) เพราะเป็นการส่งจากเซิร์ฟเวอร์ ไม่ใช่จากเครื่อง
   ลูกค้า — **นี่คือวิธีที่แนะนำ ต้อง deploy Cloud Function ให้เสร็จก่อน (ดู
   หัวข้อด้านล่าง "ทำไมขึ้นว่ายังไม่ได้ตั้งค่า LINE Messaging API")**
2. **เปิดหน้าต่างแชร์ของระบบปฏิบัติการ** (Web Share API) — ถ้าขั้น 1 ยังไม่
   พร้อมหรือส่งไม่สำเร็จ จะลองเปิดหน้าต่างแชร์ของเครื่อง (แบบในภาพตัวอย่างที่
   เป็น Windows Share) ให้ลูกค้าเลือก LINE เองได้ ใช้ได้ทั้ง Windows, Mac,
   iOS, Android ที่รองรับ Web Share API
3. **คัดลอก + เปิดหน้าแอดไลน์ร้าน** — ถ้า 2 ขั้นแรกใช้ไม่ได้เลย (เช่น
   เบราว์เซอร์เก่าไม่รองรับอะไรเลย) จะคัดลอกข้อความ+รูปสลิปไว้ในคลิปบอร์ด
   แล้วเปิดหน้าแอดไลน์ร้านให้ ลูกค้าวาง (paste) เข้าแชทเอง

**สรุป: ถ้า deploy Cloud Function (ขั้นที่ 1) เสร็จแล้วและใส่
`ORDER_SUBMIT_URL` ถูกต้อง ลูกค้าจะไม่เห็นหน้าต่างแชร์หรือต้องวางเองอีกเลย
ไม่ว่าจะสั่งจากอุปกรณ์ไหนก็ตาม**

## หน้าออเดอร์ลูกค้าแบบเรียลไทม์ (เจ้าของร้านดูได้จากเว็บโดยตรง)

เพิ่มส่วน **"ออเดอร์ลูกค้า (เรียลไทม์)"** ไว้บนสุดของหน้า `admin.html` แล้ว
— ทุกครั้งที่ลูกค้าสั่งซื้อสำเร็จผ่าน Cloud Function (ขั้นที่ 1 ด้านบน)
ระบบจะบันทึกข้อความสรุปออเดอร์ + รูปสลิปลง **Firestore** (ฐานข้อมูลของ
Firebase) ให้อัตโนมัติ แล้วหน้า admin จะแสดงผลให้ทันทีแบบเรียลไทม์ ไม่ต้อง
กดรีเฟรช ไม่ต้องเปิด LINE เลยก็ดูออเดอร์ได้

**ต้องตั้งค่า 3 อย่างนี้ก่อนใช้งานจริง:**

1. **เปิดใช้งาน Firestore** — ใน Firebase Console ของโปรเจกต์ "mine-flower"
   ไปที่เมนู Firestore Database > Create database (เลือกโหมด Production)
2. **ใส่อีเมล Google ของเจ้าของร้าน** — เปิดไฟล์ `admin-orders.js` แก้
   ```js
   const ADMIN_EMAILS = ["you@gmail.com"]; // 👈 ใส่อีเมล Gmail จริงของคุณ
   ```
   ใส่ได้หลายอีเมลถ้ามีหลายคนดูแลร้าน เช่น `["a@gmail.com", "b@gmail.com"]`
3. **ตั้งค่า Firestore Security Rules** — ใน Firebase Console ไปที่ Firestore
   Database > Rules แล้ววางกฎนี้ (แก้อีเมลให้ตรงกับข้อ 2 ด้านบน):
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /orders/{orderId} {
         allow read: if request.auth != null &&
                        request.auth.token.email in ['you@gmail.com'];
         // เจ้าของร้านอัปเดตได้เฉพาะฟิลด์สถานะออเดอร์ (ใช้ปุ่ม "บันทึกสถานะ" ในหน้า admin)
         allow update: if request.auth != null &&
                          request.auth.token.email in ['you@gmail.com'] &&
                          request.resource.data.diff(resource.data).affectedKeys()
                            .hasOnly(['status', 'statusReason', 'statusUpdatedAt']);
         allow create, delete: if false; // สร้างออเดอร์ผ่าน Cloud Function เท่านั้น
       }
     }
   }
   ```
   กฎนี้ทำให้มีแค่คนที่ล็อกอินด้วยอีเมลที่ระบุไว้เท่านั้นที่เปิดดูออเดอร์ได้
   คนอื่นแม้เข้าเว็บ admin.html ได้ก็ยังดูออเดอร์ไม่ได้ถ้าไม่ได้ล็อกอินด้วย
   อีเมลที่อนุญาต

4. **เปิดใช้งาน Google Sign-In** — ใน Firebase Console ไปที่ Authentication >
   Sign-in method > เปิดใช้งาน "Google" (ถ้ายังไม่เคยเปิด)

หลังตั้งค่าครบ เข้า `admin.html` → กด "เข้าสู่ระบบด้วย Google เพื่อดูออเดอร์"
→ ล็อกอินด้วย Gmail ที่ใส่ไว้ใน `ADMIN_EMAILS` → จะเห็นออเดอร์ล่าสุด 50
รายการพร้อมรูปสลิปทันที

> หมายเหตุ: รูปสลิปที่แสดงในหน้านี้เป็นลิงก์ที่มีอายุ 7 วัน (ตั้งไว้ใน
> `functions/index.js`) เพื่อไม่ให้ข้อมูลการเงินของลูกค้าเปิดเผยสู่สาธารณะ
> ตลอดไป ถ้าต้องการดูสลิปของออเดอร์เก่ากว่า 7 วัน แจ้งได้ ปรับเพิ่มอายุลิงก์
> หรือเปลี่ยนวิธีเก็บให้ได้

## สถานะออเดอร์ (ทุกอุปกรณ์)

เจ้าของร้านเลือกสถานะในหน้า `admin.html` ที่การ์ดออเดอร์แต่ละใบ แล้วกด "บันทึกสถานะ":
ยังไม่ได้สั่ง → สั่งไปแล้ว → กำลังไปส่งออเดอร์ → ออเดอร์ส่งเสร็จแล้ว หรือ ยกเลิกออเดอร์
(ต้องกรอกเหตุผล) ลูกค้าเห็นสถานะในส่วน "ประวัติการสั่งซื้อ" (เมนู 3 ขีดบนมือถือมีลิงก์ลัด)
และอัปเดตเองทุก 30 วินาที

ต้องทำเพิ่ม: 1) แก้ Firestore Rules ตามด้านบน (มี `allow update`)
2) `firebase deploy --only functions` 3) เอา URL ของ `orderStatus` ไปใส่
`CONFIG.ORDER_STATUS_URL` ใน `inventory-config.js` และ URL ของ `submitOrder` ใน `CONFIG.ORDER_SUBMIT_URL`
แก้ชื่อสถานะได้ที่ `ORDER_STATUSES` ใน `inventory-config.js`
